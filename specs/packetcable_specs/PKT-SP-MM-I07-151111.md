# PKT-SP-MM-I07-151111 - Multimedia Specification

## Document Information
- **Title**: Multimedia Specification
- **Document Control Number**: PKT-SP-MM-I07-151111
- **Status**: Issued
- **Date**: November 11, 2015
- **Publisher**: Cable Television Laboratories, Inc. (CableLabs)

## Purpose
This specification supports deployment of general Multimedia services by providing technical definitions for IP-based signaling interfaces that leverage DOCSIS QoS and policy management capabilities. It generalizes the PacketCable 1.x telephony-focused framework for broader multimedia applications.

## Scope
- Network-based QoS resource management
- Usage auditing capabilities
- Support for "legacy" Client Type 1 devices
- Proxied QoS with Policy Push scenario
- Access network QoS (backbone QoS is provider-specific)

## Relation to PacketCable 1.x
PacketCable Multimedia extracts the functional core of PacketCable 1.x:
- **Retained**: QoS mechanisms, event messaging, security infrastructure
- **Not Required**: Telephony-specific features (NCS, PSTN interconnection, electronic surveillance)

## Key Topics

### Architecture (Section 5.2)
- **Session Control Domain (SCD)**: Application servers and managers
- **Resource Control Domain (RCD)**: CMTS and Policy Server entities

### PacketCable Multimedia Devices
- **Application Server**: Processes client requests, converts to session requests
- **Application Manager**: Maintains session-level state, enforces SCD policies
- **Policy Server**: Intermediary between Application Manager and CMTS
- **CMTS**: Policy Enforcement Point, manages DOCSIS service flows
- **Record Keeping Server (RKS)**: Collects event messages

### Client Types
- **Type 1**: Legacy endpoints without QoS awareness (current support)
- **Type 2**: PacketCable DQoS-capable (MTA-like)
- **Type 3**: RSVP-capable direct QoS signaling

### Authorization Interface (Section 6)
- **Gates**: Framework for QoS control
  - GateID, Application Manager ID (AMID), Subscriber ID
  - Gate Specification (GateSpec)
  - Classifiers (IPv4, IPv6, extended)
  - Traffic Profiles (FlowSpec, DOCSIS Service Class)
  - Event Generation Info
  - Time-Based and Volume-Based Usage Limits

### Gate States
1. **Authorized**: Resources authorized, awaiting reservation
2. **Reserved**: Resources admitted by DOCSIS
3. **Committed**: Resources active
4. **Committed-Recovery**: Recovery after CMTS restart

### COPS Profile (Section 6.3)
- Client-Type: 0x800A (PacketCable Multimedia)
- Based on COPS-PR provisioning model
- Gate Control messaging via COPS Decision objects

### Gate Control Messages
| Message | Direction | Purpose |
|---------|-----------|---------|
| Gate-Set | PS→CMTS | Create/modify gate |
| Gate-Set-Ack | CMTS→PS | Confirmation |
| Gate-Set-Err | CMTS→PS | Error response |
| Gate-Info | PS→CMTS | Query gate state |
| Gate-Info-Ack | CMTS→PS | State response |
| Gate-Delete | PS→CMTS | Remove gate |
| Gate-Delete-Ack | CMTS→PS | Confirmation |
| Gate-Report-State | CMTS→PS | State change notification |

### Event Messaging (Section 7)
- **Policy Events**: Policy_Request, Policy_Delete, Policy_Update
- **QoS Events**: QoS_Reserve, QoS_Commit, QoS_Release
- **Time_Change**: System time synchronization

### Security (Section 8)
- IPsec for COPS interfaces
- IPsec for RADIUS interfaces

### DOCSIS Mapping (Section 9)
- FlowSpec to DOCSIS scheduling types
- Upstream: UGS, Real-Time Polling, Best Effort
- Downstream: Guaranteed Service, Controlled Load

## Key Concepts

### Resource Envelopes
Three envelope types for QoS authorization:
- **Authorized Envelope**: Maximum resources allowed
- **Reserved Envelope**: Resources currently reserved
- **Committed Envelope**: Resources currently active

Rule: Authorized >= Reserved >= Committed

### Multicast Support
- DOCSIS 3.0 multicast QoS framework integration
- Single-Session Group Service Flows
- Overrides IP Multicast Join Authorization
